# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**ROPlanesPlus (`ROPlanes+`)** — a Kerbal Space Program 1.12 aircraft mod for the RSS / RealismOverhaul / RP-1 stack (plus FAR, AJE/SolverEngines, Kerbalism, RealAntennas). It ships:
- 10 historical cockpit parts, modelled/baked/painted in **Blender** at real size, each with B9PartSwitch versions (e.g. radome vs. open front, canopy styles) and 3 switchable paint schemes; every rear ring is a true circle of a standard diameter.
- 1 procedural launch pylon (`ROPlanes-ProcPylon`, added 2026-11-19 at the user's request: a drop pylon that **stays on the part it is mounted to** and releases the aircraft on its hook face, unlike a stock radial decoupler which stayed hanging from the launched plane), see "Launch pylon" below.
- 1 procedural propeller engine part (`ROPlanes-ProcProp`) driven by a C# plugin (`ROPlanesPlus.dll`) that rebuilds meshes, reconfigures AJE, plays RPM-tracked engine audio and provides the Engine Workshop window. The old per-type parts (`ROPlanes-ProcProp-Radial/-VInline/-Turboprop/-Contra`) were removed on purpose; `generate_configs.py` deletes their folders and the verifier fails if they come back.

The shippable mod is `GameData/ROPlanesPlus/`. **Almost everything in it is generated** — models, textures, icons, sounds and `.cfg` files come from the Python scripts at the repo root; the DLL comes from `Source/`. Edit the generators/source, then regenerate; don't hand-edit generated output (it will be overwritten).

This is not a git repo and has no test suite beyond the verification script. A local KSP install with the full RO/RP-1 stack lives at `D:\SteamLibrary\steamapps\common\Kerbal Space Program` (its `KSP.log`, `GameData/ModuleManager.ConfigCache`, `GameData/AJE/*.cfg` and `GameData/RP-0/Tree/TREE-Parts.cfg` are the references for balance and for checking how patches resolve). `GameData/ROPlanesPlus` there is a deployed copy of this repo's output (deploy with `robocopy GameData\ROPlanesPlus <KSP>\GameData\ROPlanesPlus /MIR`).

## Commands

All commands run from the repo root (Windows / PowerShell). Python scripts use only the standard library (no pip deps), except `process_recordings.py` (the recorded engine loops), which needs `numpy`, `scipy` (`pip install --user numpy scipy`, installed 2026-11-17) and `ffmpeg` (winget `Gyan.FFmpeg`, found via PATH or the WinGet folder). Without them `generate_sounds.py` warns and falls back to the synthesized versions. Don't run them with `python -I`: `generate_propeller_assets.py` imports `generate_models_and_textures.py` from the script directory. The cockpit build needs **Blender** (installed via winget at `C:\Program Files\Blender Foundation\Blender 5.3\`; `$env:BLENDER` overrides) and uses Blender's bundled Python + numpy.

```powershell
python generate_cockpits.py [ids] [--no-preview]   # Blender, background: cockpit .mu + liveries + NRM + emissive + glass + @thumbs icons (~2-4 min per cockpit at 2048 px); without ids also cockpits_preview_sheet.png; per-variant/livery renders go to build/cockpit_previews/
python generate_cockpits.py [ids] --quick          # shape check only (no bake/paint/.mu): side, top, front-3/4 and cockpit close-up per version -> build/quick/<id>__<version>.png (EEVEE; $env:ROPP_QUICK_ENGINE='CYCLES' forces Cycles)
python generate_propeller_assets.py      # Parts/PropShared: proc_prop.mu, 14 livery maps, paint kit, ropp_NRM, emissive, disc + icon (~30-80 s)
python generate_pylon_assets.py          # Parts/proc_pylon: proc_pylon.mu, 5 tiling paint maps, NRM, hardware texture + icon (~5 s)
python generate_sounds.py                # Sounds/*.wav (28 loops/one-shots; 14 loops from real recordings via process_recordings.py, the rest synthesized; deletes any other .wav there; writes Sounds/CREDITS.txt)
python generate_configs.py               # all part .cfg files + Compatibility/*.cfg MM patches (cockpits AND the engine)
powershell -ExecutionPolicy Bypass -File build_plugin.ps1   # compile GameData/ROPlanesPlus/Plugins/ROPlanesPlus.dll
python verify_mu_and_configs.py          # validate everything under GameData/ROPlanesPlus
```

## Architecture

### Cockpit pipeline (Blender)
- `cockpit_specs.py` (pure Python, shared by Blender and `generate_configs.py`) holds each cockpit's design data in **design space**: metres, `y` forward with the **rear ring at y = 0** (a true circle of `rear_dia`), `z` up, `x` starboard; part origin = pilot station `origin_y`. Fuselage = PCHIP-interpolated keyframes `K(y, w, ht, hb, zc, nt, nb, ch, cha)` (superellipse halves, optional chine) + optional nose closure `(1 - t^p)^q`; canopy bubbles `C(y, wc, ztop, nc)` (sill height computed so the bubble sinks into the body); `frames` (bows/rails), `glazing` patches (bomber greenhouses), `details` (pitot, blade, ball, box, turret, blister), variant `extra`. `split_y` separates the common body from per-version noses: `nose: 'native'` (continues the loft / MiG intake) or `'adapter'` (morphs to a round `front_dia` ring + cap). Variants may also override `body`, `canopy`, `frames`, `glazing`, `length`. Liveries: `L(...)` (solid/camo/splinter/digital/metal patterns, under/belly split, mottle, whitewash, anti-glare, radome, frame colours, `lip` intake-lip colour, `soot` strength, `decals=[D(text, y, z, h, colour, outline)]` painted numbers/lettering projected sideways, rendered from a bold system font). Cockpit-level `stencils` (same `D(...)`) go on every livery, `exhaust` = soot streaks `(y0, z0, length, width, droop)`.
- Real sizes: the Spitfire and Bf 109 use 0.9375 m rings (their real ~0.9 m fuselage width; changed from 1.25 m on 2026-11-16 at the user's request, so craft saved before then need those parts re-attached). The other cockpits keep their rings.
- **Cockpit interior** (`pit` in the spec): the body loft leaves an opening (`y0..y1`, half width `w` → constant-phi cut) under the canopy, and every glazing patch is cut too; `compartment()` adds an inward liner (cut the same way, with rims closing the 2 cm gap), bulkheads, a two-sided floor (`floor`), instrument panel(s) (`panel_y` / `panels=[(y, top)]`, `panel_w`) with a glareshield hood, gunsight (`sight`: `reflector` / `hud`), seats (`seat`: `ww2` / `ejection` / `bomber`, `seat_z`, `recline`, `headbox`; `seats=[(x, y, z, {overrides})]` for multi-crew), stick (`stick` / `side` / `yoke` / None) and side consoles. Colours: `col`, `panel_col`, `seat_col`, `accent`; dials are painted procedurally (`dial_w`, `dial_sp`) and glow in the emissive map.
- `blender/build_cockpits.py` builds clean lofted quad meshes from the specs, unwraps (own arc-length UVs for lofts, smart projection for small parts, per-class texel scaling, one packed atlas), bakes position/normal/class/coverage (EMIT) and per-variant AO with Cycles, then paints with numpy: liveries (`<id>_<livery>.png`, RGB + gloss in A), `<id>_NRM.png` (panel lines, staggered seams, hatches, rivets from the baked positions), `<id>_emissive.png` (half res: canopy glow, F-16/F-4 formation lights). Writes `<id>.mu` via `MuWriter` (export maps design → KSP `(x, y - origin_y, -z)` and **reverses winding**; tangents computed in numpy), the `@thumbs` icon and previews. Material: `KSP/Emissive/Bumped Specular` (tex 0 = first livery, 1 = emissive, 2 = NRM as normal map) + `KSP/Alpha/Translucent` flag.
- `.mu` layout: root `cockpit` → common `fuselage` (with `airlock`/`ladder` triggers), `windows`, `canopyInterior`, `flagDecal`, `intakeTransform` (MiG-15 only; +Z rotated to point forward, used by `ModuleResourceIntake`), then one `variant_<key>` group per version holding that version's own `fuselage`/`windows`/`canopyInterior` meshes, an `intakeDuct` mesh (inward-facing duct/splitter, intake versions only) and 1–4 convex `collider` segments (hulls of analytic samples, < 255 tris). B9PartSwitch toggles the groups by name, moves the `top` node per version and swaps `_MainTex` (`currentTexture = <id>_<first livery>`). Lights use `ModuleColorChanger` on `_EmissiveColor` (no animation).
- **Plain White default + colour mods (2026-11-16, user request):** every cockpit's first livery is `white` ("Plain White", `PLAIN_WHITE` in `cockpit_specs.py`, inserted in a loop after the cockpit list; `clean=True` = no soot). Painted numbers/lettering/stencils were removed from all schemes (the `D(...)`/`stencils` machinery still works but no spec uses it); the historical schemes stay as later options. Colour-mod support:
  - **TexturesUnlimited:** each build also writes `<id>_paint.png` (greyscale where recolourable, normalised so clean paint = 0.5 = `_DiffuseNorm`; real colours on caps etc.), `<id>_mask.png` (half res; R upper surfaces, G lower surfaces, B detail = frames, anti-glare, radome, intake lip) and `<id>_metal.png` (half res; R metallic, A smoothness, 0.5 where recolourable). `format_tu_config()` writes `Compatibility/TexturesUnlimited_Cockpits.cfg` (all `:NEEDS[TexturesUnlimited]`): `KSPTextureSwitch` + `SSTURecolorGUI` replacing the B9 `cockpitPaint` module, the recolourable `ROPP-<id>-recolor` ("Plain White (recolourable)") **first and default** — TU's `SSTURecolorGUI` only shows its "Open Recoloring GUI" button while the *current* set is recolourable (the first version defaulted to a fixed set, so users saw no button) — then one fixed set per historical livery (`TU/Metallic` + `TU_STOCK_SPEC`, gloss from the livery alpha, `_Emissive` so Cockpit Lights still work), and `KSP_COLOR_PRESET`s in the `ROPlanes+ Aircraft` group. Sets exclude `windows`, `flagDecal`, `canopyInterior` (`TU_EXCLUDE`). TURD / Recolour Collection / Lazy Painter work through these sets.
  - **SimpleRepaint** (B9PartSwitch `moduleID = SimpleRepaint`, `_Color` per MATERIAL; B9 picks renderers by transform, and with none it tints every renderer with `_Color`): `Compatibility/SimpleRepaint_Cockpits.cfg` (`:NEEDS[SimpleRepaint]:AFTER[zzzzzzSimpleRepaint]`) adds `transform = fuselage` to its MATERIAL nodes so glass and interior stay untinted. With TU installed SimpleRepaint ignores parts that have `KSPTextureSwitch`.
  - **Reforged Materials** (adds `ModuleReforged` to every part, swaps to `TU/Metallic`): no patch; it skips renderers whose names contain window/glass/canopy/flag/overlay — hence the interior node name `canopyInterior`.
  - None of this is tested in game yet.
- Materials: 0 = fuselage skin `<id>_mat` (`KSP/Emissive/Bumped Specular`, livery / emissive / NRM), 3 = cockpit interior `<id>_interior_mat` (same shader and textures, separate so tint-based colour mods leave it alone), 1 = flag decal, 2 = canopy glass (`KSP/Alpha/Translucent Specular` with its own `<id>_glass.png`, RGB tint + A opacity, half resolution; spec keys `glass` tint and `glass_alpha` (side, top)). Glass classes (`glass`, `dome`) are hidden from the AO bake so the interior is lit through them.

### Python asset pipeline
- `generate_models_and_textures.py` is now only the shared library: pure-Python PNG encoder (`write_png`), KSP `.mu` v5 writer (`MuWriter`), `MeshBuilder`, math helpers. `generate_propeller_assets.py` and `blender/build_cockpits.py` import it — changes to `MuWriter` affect both.
- Propeller assets are **shared**: the engine part loads `Parts/PropShared/proc_prop.mu`, whose materials reference `ropp_livery_usn`, `ropp_NRM` (normal map, `.mu` texture type 1), `ropp_emissive` and `ropp_disc` in the same folder. `Parts/proc_prop/` only holds the `.cfg`. Shader is `KSP/Emissive/Bumped Specular` (disc: `KSP/Alpha/Translucent`).
- `generate_texture_set()` builds livery-independent layers once (height for the normal map, base colours for engine internals/exhausts/blades, paint masks), then composites the 14 liveries (`spinner_colour`/`cowl_colour` per key) and the **custom paint kit**: `ropp_paintkit_base.dat` (RGBA; painted texels = grey shade where 200 = clean paint, A = gloss factor) and `ropp_paintkit_mask.dat` (R: 0 unpainted, 85 cowling, 170 nose ring, 255 spinner). The kit is PNG data with a `.dat` extension so GameDatabase doesn't load it; `Paint/CustomPaint.cs` decodes it with `ImageConversion.LoadImage`. `LIVERY_KEYS` must match `PropellerPresets.LiveryKeys` (which adds `custom` last) and `LiveryOptions` order; livery display names are persisted in craft, so only append.
- `generate_configs.py` has separate data tables: `COCKPIT_CONFIGS` (gameplay values: mass, crew, IVA, RP-1 tech/cost, Kerbalism hab, BDArmory HP/armour; geometry/variants/liveries come from `cockpit_specs`) and `PROPELLER_CONFIGS` (one entry: the engine part). `generate_all_configs()` writes per-part `.cfg` files (cockpits: nodes from the specs, two `ModuleB9PartSwitch` modules `cockpitVersion`/`cockpitPaint`, `ModuleColorChanger`), `RP1_Cockpits.cfg`, `RO_Kerbalism_FAR_RealAntennas.cfg`, `BDArmory_Cockpits.cfg` (`%MODULE[HitpointTracker]` with `maxHitPoints`/`ArmorThickness`/`maxSupportedArmor`/`hullType`, `:NEEDS[BDArmory]:AFTER[BDArmory]`, untested in-game) and then calls `generate_propeller_configs()`, which also writes `RO_AJE_FAR_ProceduralPropellers.cfg` and `RP1_ProceduralPropellers.cfg` in `Compatibility/` and removes `REMOVED_PART_DIRS`.
- **ModuleManager pass rule:** `:FOR[X]` *declares* mod X installed, which would switch on every other mod's `:NEEDS[X]` patches in games without X (e.g. the RealAntennas patch strips the stock antenna, FAR/RO/AJE/RP-0 patches of other mods activate). `sanitize_mm_passes()` (end of `generate_all_configs`) rewrites every foreign `:FOR[X]` to `:NEEDS[X]:AFTER[X]` (`MM_PASS_RULES`; AJE → `:BEFORE[AJE]` so AJE's own passes see `ModuleEnginesAJEPropeller`; RP-1's `xxxRP0`/`xxxRP-0`/`zRP-0` passes get `NEEDS[RP-0]`, merged into an existing NEEDS with `&`). The verifier fails on any `:FOR[` in a patch header.
- **Fuel:** the engine's fuel `PROPELLANT` uses `resourceFlowMode = ALL_VESSEL_BALANCE` (the key `Propellant.Load` reads — not `flowMode`), so wing-mounted engines don't depend on crossfeed through wing roots; `UpdateEnginePropellant` also rebuilds older craft's propellants that way. RP-1 costs: pistons 8 + 0.0085 × hp (× 1.2 contra), turboprops 4 + 0.0267 × shp (fitted to the contra NK-12M = 400); RP-1 v1.12 has no tooling or KCT tags for AJE engines.
- A part's identity is spread across files: `id` (folder / `.mu` name, e.g. `spitfire`, `proc_prop`) and `part_name` (e.g. `ROPlanes-ProcProp`, used for MM `@PART[...]` and `@thumbs/<part_name>_icon.png`) must match between the asset spec and the config entry.

### Texture UV layout (shared contract between Python textures, Python meshes and `PropellerMeshGenerator.cs`)
- V 0.00–0.45 cowling skin: U around the circumference with **U=0/1 on top (dorsal, −Z)** and U=0.5 underneath; V aft→nose (nose ring at V/0.45 ≈ 0.885–0.935).
- V 0.45–0.65 engine internals: U<0.5 finned cylinders, 0.5–0.75 crankcase + pushrods, ≥0.75 radiator/intake grille.
- V 0.65–0.80 exhaust stubs (base→hot tip), also the only emissive band.
- V 0.80–1.00 U<0.70 blades (U root→tip, V chord), U≥0.70 spinner.

### Coordinate & mesh conventions (enforced by the verifier)
- `+Y` forward (nose/spinner, `node_stack_top`), `-Y` aft, `-Z` dorsal/up, `+Z` ventral/down, `+X` starboard.
- Normals point outward; each triangle's `cross(v1-v0, v2-v0)` must have positive dot with the vertex normals.
- Outwardness (verifier): `fuselage`/`windows` meshes are split into connected pieces (by vertex position); pieces longer than 0.6 m need faces pointing away from their own centreline (mid x/z per 5 cm slice — handles drooped noses and off-axis blisters), shorter pieces (frames, domes, blades) need positive area-weighted flux about their centroid (flat end caps: about the part origin); > 85 % of faces must pass. `collider` 100 % away from its own centroid, `flagDecal` away from the origin, `intakeDuct` is only winding-checked. An inside-out tube is rejected (mutation-tested).
- Required `.mu` node names — cockpits: `fuselage`, `windows`, `canopyInterior` (inward-facing, winding-checked only), `flagDecal`, `collider`, `Airlock`/`Ladder` tags on layer 21, at least one `variant_*` group; each cockpit folder also needs `<id>_glass.png`, `<id>_emissive.png`, `<id>_NRM.png`, `<id>_paint.png`, `<id>_mask.png`, `<id>_metal.png`. Propellers: `CowlingMesh`, `EngineCoreDetailsMesh`, `ExhaustAndRadiatorMesh`, `CowlFlapsMesh`, `FrontPropHub`, `RearPropHub`, `SpinnerMesh`, `RearSpinnerMesh`, `FrontBladesMesh`, `RearBladesMesh`, `FrontRotorDisc`, `RearRotorDisc`, `cowlingCollider`, `spinnerCollider`, `thrustTransform`, `exhaustPortL`, `exhaustPortR`. The plugin looks these up by name (the part cfg has no `EFFECTS` block; all effects come from `Effects/EngineEffects.cs`).

### C# plugin (`Source/ROPlanesPlus/`, namespace `ROPlanesPlus`)
- `Presets/PropellerPresets.cs` — enums, option strings, liveries (names, keys, picker swatches), the Custom Paint palette/finishes, and the 14 presets. Each preset carries geometry, realistic mass (dry engine + propeller), **the exact AJE block** (copied from AJE's own configs where they exist; see comments), `techRequired` (RP-1 node) and `wepMultiplier`. `PROPELLER_CONFIGS` in `generate_configs.py` duplicates the default preset (R-2800) — keep ids, strings and AJE numbers in sync. `GetPreset()` maps legacy ids from older saves.
- `Physics/PropellerPhysicsEngine.cs` — `Evaluate()` produces `PropellerPerformanceMetrics` (incl. `AJEParameters`): preset values verbatim, or `DeriveCustom()` rules for *Custom* engines (displacement from hp = 5.2e-6 × MAP × RPM × cu in). Design rules live here: `CylinderCount`, `GetPowerLimits` (1.0–4.2 L per cylinder at the chosen boost/RPM, plus absolute caps per layout; turboprop classes by layout), `AutoCowl` (cowling from cylinder size and row count), `CustomMassTons` (dry engine + supercharger/turbo + blades/hubs + contra gearbox), `OptimalPropDiameter`. Contra Ct gain comes from `PerformanceModel.ContraThrustGain` (swirl recovery vs disk loading, ~5–14 %). `AJEBridge` wraps all AJE access by cached reflection (most config fields `double`; `CtTweak/CpTweak/VolETweak/MachPowTweak/propRPM/propPitch/brakeShaftPower` `float`; `Set()` converts) and calls `SetUnits()`+`CreateEngine()`, the solver's `SetTweaks` (WEP via `VolETweak`) and the JSB prop's `SetFeather`. AJE's propeller model applies no torque (only its rotor modules call `AddTorque`). Never add a hard reference to AJE/FAR; without AJE a stock fallback sets thrust and an Isp matched to BSFC.
- `Physics/PerformanceModel.cs` — ISA atmosphere, power vs altitude from the AJE supercharger stages, momentum-theory thrust with swirl and tip-Mach losses, fuel burn. Used for the Workshop numbers and `staticThrustKn`.
- `Modules/ModuleProceduralPropeller.cs` — the `PartModule`. Uses Unity `Update()`/`FixedUpdate()` (not `OnUpdate`). Design fields are plain persisted `KSPField`s (`DesignFieldNames`, incl. `autoCowl`, `propStrikes`, `autoFeather`, `paintCowl/Nose/Spinner/Finish`); the part menu only shows name/spec, flight status and Feather/WEP/Reverse (the Workshop button comes from `ModuleEngineWorkshopButton`). Changing any field in `EngineSignature()` flips the preset to `Custom`. `RebuildEverything()` → (custom) `EnforceEngineLimits` → `Evaluate` → `ApplyCowlSizing` (auto-fit, or manual clamped to the engine's size) + `EnforcePropClearance` → meshes → exhaust anchors → livery → `ApplyToEngineModules` → FAR rebuild. `ChangeArchitecture` keeps engine weight (turboprop ≈ 2.5× piston power). Flight: live AJE state drives spin, blade-to-blur-disc crossfade, collective pitch (`BuildBladesOnly`), automatic cowl flaps, exhaust glow, effects, audio, **prop strikes** (radial raycasts in the prop disc against terrain/scenery layers 15/28, water only over the sea; breaks the prop and locks out restarts) and **auto-feather** for turboprops. **Runtime meshes must be created through `MeshFilter.mesh`** (`DuplicateMeshFilter`), never `new Mesh()` + `sharedMesh`: Firefly (`AtmoFxModule.CalculateVesselBounds`, on every vessel modification), KSPCF drag cubes and Deferred read `MeshFilter.mesh`, which in Unity clones a mesh the filter doesn't own and puts the clone on screen — after that every in-place rebuild (bent blades, blade pitch, cowl flaps) was invisible while material changes still showed. `ReclaimMeshes` (after each rebuild and in the 0.3 s `EnsureMaterials` pass) puts our mesh back if anything still swaps it. Liveries: `ApplyLivery` picks the GameDatabase map or a `CustomPaint` texture; `EnsureMaterials` runs every 0.3 s because other installed mods (Deferred, TU, KSPCF, …) replace part materials — it re-assigns ours if the renderer went back to the prefab material, or clones another mod's private copy and paints the clone (never paints shared materials).
- `Paint/CustomPaint.cs` — composites Custom Paint liveries from the kit at runtime (cached per colour combination, compressed to DXT).
- `Physics/EngineStartSequence.cs` — start-up/shut-down model (`EnginePhase` Off → Cranking → Catching → Running), shared by the module and the Workshop's "Listen" preview. Piston: starter spin-up and engage, cranking at 110-190 engine rpm (longer when cold), single cylinders coughing in (occasional stumble), catch, flare and idle (620/700 engine rpm); cold engines misfire (`Warmth`). Turboprop: starter turns the gas generator (`CoreN`) and single-shaft prop, igniters, light-off at ~13 % after 3-5 s, then an ease-out acceleration to ground idle 70 % (PT6 ≈ 9 s, NK-12 ≈ 17 s in total). `OffDecel` = friction/compression after shutdown. Raises event flags (`TakeEvents`) for sounds/effects. **Synchronized starts (2026-11-17, user report: engines started together each started at their own time, and overlapped radials buzzed):** `StartSeed` is asked for a seed in `Begin()`. `ModuleProceduralPropeller.StartGroupSeed` returns one seed per vessel for every start beginning within 1.5 s of the first (`StartGroups`, keyed by `vessel.id`), so engines switched on together draw the same cranking time, catch, stumble and coughs and run in step. Once running, each reseeds from its own unique seed (`NewRng`; plain `new System.Random()` seeds from the clock and repeats within a millisecond). In a replica using the real sequence code, four cold R-2800s reached Running at 6.2–8.3 s before and all at 6.16 s after. The Workshop preview has no `StartSeed`. AJE's own start is a 20 %-power "starter" below 60 shaft rpm, zero throttle is "magnetos off", and it has no engine friction, so `ModuleProceduralPropeller.DriveAJEPropeller` writes AJE's propeller RPM (`AJEBridge.SetPropRPM`: JSB `RPM` + solver `propRPM`) while starting, as a piston idle floor at closed throttle (turboprops: only when the throttle opens, since their idle is zero-thrust ground fine), and with `OffDecel` once shut down. Running thrust/power stay pure AJE. Windmilling air-starts skip cranking.
- **Piston design model** (`PropellerPhysicsEngine`): cylinders = rows/banks from the layout (`CylinderRows`: radial sub 1/0/2 = 1/2/4 rows, inline V = 2 banks, X = 4) × `cylindersPerRow` (radial 5/7/9, inline 4/6/8; 0 = layout default; presets may set it, ASh-82 = 7). For custom pistons the master values are `cylinderLitres` and `boostInHg` (0 = supercharger default, clamped to `BoostRange`); `EnforceEngineLimits` derives `shaftPowerHP = PowerFromLitres` (5.2e-6 × boost × rpm × cu in, the same relation `DeriveCustom` gives AJE). `FreezeDisplacement` (called before any engine edit in the Workshop and in `EnforceEngineLimits`) turns a preset into a custom design without a power jump: it keeps the preset's real displacement and sets the boost that reproduces its power. Cowl sizing: `BoreStroke` (stroke/bore 1.08) → `EngineWidth` (radial ≈ 0.24 + 6.3 × stroke; V = deck height + bore + 0.1; X ×1.41) → `AutoCowl(m, aje, fit)` with `cowlFit` 0 tight / 1 standard / 2 roomy (Merlin 66 and DB 605 presets default to tight: DB 605 = 0.93 m, fits the Bf 109's 0.9375 m ring); `MinCowlDiameter` = the tight fit. The mesh draws `cylindersPerRow` cylinders per radial row and one ejector stub per cylinder per bank. Custom piston mass = (radial 0.020 / inline 0.070 t) + 18 kg per litre swept + 0.12 kg/hp (+ supercharger extras); rpm is capped by `PistonSpeedLimitRPM` (17 m/s mean piston speed: 3 L → 3050 rpm, 5 L → 2600); boost above the supercharger default costs +0.4 % BSFC per inHg.
- **Prop strikes:** `CheckPropStrike` (12 radial raycasts per 0.06 s, skipped above `radarAltitude` = prop diameter + 25 m) → `ApplyPropStrike`: `propDamaged` + random `propDamageSeed`, engine shut down, AJE prop pinned to 0 rpm every frame and the visual stopped at once (no coast-down), blades rebuilt bent (`BuildHubSubMeshes(..., damageSeed)`, matched to photos of real strikes: each blade folds about its chord line at full width — 78 % aft, the rest forward — by 60-200°, as a sharp fold or a curl tightening into a hook, built by marching along the span and rotating every section with the bend; 25 % also lose the tip with a torn edge. `AxisAngle` is a managed `Quaternion.AngleAxis` so the builder runs outside Unity; `DebugBladeSink` lets a harness dump the blade buffers to OBJ) with the `ropp_blades_damaged` texture on a cloned material (`EnforceDamagedBlade` in `EnsureMaterials`), dirt/sod + tumbling blade-shard mesh particles (world collisions) + sparks (more on runways) or water spray (`EngineEffects.PropStrike`), `prop_strike` / `prop_strike_water` with every engine layer cut (all-metal modal synthesis in `generate_sounds.py`: blade clangs from cantilever/torsion/plate mode ratios, stick-slip bending screech, snaps, crankshaft-seizure clang, scrape, bouncing fragments). An engineer on EVA can fit a new propeller on the ground (`ReplacePropellerEvent`). Optional `propTorque` (Options → Realism, default off): shaft-torque reaction on the airframe, none for contra-props.
- **Propeller rotation (2026-11-17, user request, for balancing torque):** `propRotation` (0 = clockwise / 1 = counter-clockwise, seen from behind looking forward) and `handedPair` (symmetry: engines on the other side turn the other way). Both are in the Workshop's Options tab (PROPELLER ROTATION) and in `DesignFieldNames` + `FullSignature`, but not in `EngineSignature`, so they don't make a preset Custom. `SpinSign` (= −1 for clockwise) drives the hub/disc spin (Unity: a positive Euler angle about +Y is clockwise seen from in front), the torque (`AddTorque(-SpinSign·τ·up)`: clockwise rolls the aircraft left) and the blade handedness (`FrontBladeSense = -SpinSign`; the rear contra row is the mirror image). Before this change the hub spun the opposite way to the blade shapes (leading edge moving last, scimitar tips leading). The fix makes the default (0) clockwise from the cockpit, so old craft now spin the other way and their torque is reversed. Pusher blades are no longer Y-mirrored (that flipped their handedness); they are only moved to the mirrored hub plane (`bladeY`). Symmetry: `SyncToSymmetryCounterparts` uses `RotationFor`, and the group's master engine (lowest `persistentId`) re-applies handedness in `EditorUpdate`, because KSP places symmetry copies as clones. Sides are split by the plane halfway between the master and its first counterpart. Verified offline with a console harness (`DebugBladeSink` + reflection into `BuildHubSubMeshes`): 24 combinations (rotation × tractor/pusher × single/contra front+rear × paddle/scimitar) have the leading edge moving first and forward and scimitar tips trailing; a control run of the old spin direction fails as expected. Side assignment in a symmetry group has not been run in KSP (it needs real Parts). Cowl flaps animate via `BuildFlapsOnly` (not a full rebuild); editor design checks run at 10 Hz.
- `Audio/PropellerAudio.cs` — layered mixer driven by `EngineSoundInput` (built in `ModuleProceduralPropeller.BuildSoundInput` or the Workshop preview). Piston: `<radial|vinline>_idle/_mid/_high` loops at 800/1600/2600 rpm made with 18 / 12 cylinders, played at the *equivalent* rpm (rpm × cylinders / 18 or 12, i.e. by firing frequency) so any cylinder count works; `_mid_off/_high_off` (closed throttle: soft uneven firing, crackle, pops) equal-power crossfaded against the on-load loops by load; afterfire pops after a throttle chop; slow random gain/pitch drift; `wind` (120 m/s ref, played by the first propeller part of the active vessel); misfire volume dips from `Roughness`; `piston_crank` (20 compression strokes/s ref) while the starter is engaged; `supercharger_whine` (2600 rpm ref, ×1.24 in high blower gear from AJE `_boostMode`, turbo speed for turbo types). Turbine: `turbine_whine` pitched by N, `turbine_roar` by power, `turbine_igniter`. Prop: `prop_loop`/`prop_rasp` (80 Hz blade-pass ref, loudness from helical tip Mach and load) and `prop_swish` (8 Hz ref, slow propeller). Directivity vs. camera angle, distance low-pass, IVA muffling, thin-air attenuation, manual Doppler for other vessels, random loop start offsets. Keep the reference constants in sync with `generate_sounds.py` and `process_recordings.ref_firing`. `ModuleEnginesFX` has no `runningEffectName`. Piston loops contain their aircraft's real propeller, so the prop layer plays at 0.5 on piston engines and 0.8 on turboprops (the recorded blade slaps are peaky), and the wind gain is 0.75 (was 0.55) because the recorded wind loop sits 3 dB lower. These gains were chosen with an offline Python replica of the mixer (scripted idle → take-off → cruise → chop runs per preset, comparing A-weighted level, brightness and clipping at full ship volume against the old synthesized sounds). The replica is not in the repo; its renders are in `build/sound_previews/`. **Several engines on one vessel** (`Instances`, a static list of every flight `PropellerAudio`):
  - All engines take the slow pitch drift and rough-running wobble of one `PitchLeader()`, so identical loops never detune against each other. Separate random detuning of up to ±2.5 % made their harmonics beat.
  - `StartLoop` places a starting loop as far as possible from the same clip on the vessel's other engines (best of 24 candidates), because copies a few ms apart comb-filter. A `Layer.alignDivisions` > 0 restricts it to a grid instead; the supercharger uses 1, for its one slow vibrato per loop.
  - One-shots are delayed by `VesselSlot()` × 0.07 s + 0–0.04 s, because synchronized coughs from four engines stacked to twice the peak.
  - `piston_crank` no longer contains a starter-motor tone. It was pitched by compression strokes, so on big radials it sat next to `starter_whine` (≈173 vs 202 Hz) and the two beat into a buzz. It is now chugs and gear rattle, and `starter_whine` is the motor.
- **Recorded loops (2026-11-17, user request "better sounds", chose real recordings over better synthesis):** `process_recordings.py` builds `radial_*`, `vinline_*`, `turbine_whine`, `turbine_roar`, `prop_loop` and `wind` from CC0/CC-BY Freesound recordings in `sound_sources/` (`originals/<id>.wav` = full-quality downloads, present for all 9 sources; `previews/` HQ Oggs are the fallback; NonCommercial sources deliberately excluded). Sources:
  - **Radial: single-engine recordings only.** Idle is a PZL-104 Wilga (9-cyl AI-14R) recorded close. Mid and high are both cut from a P-47 (R-2800) approach, which makes their crossfade seamless.
  - The first radial set (twin C-47, a four-engine airliner, twin B-25) carried the beat of unsynchronised engines baked in: harmonic lines pulsed 53–57 %, which the user heard in game as a "wooow wooow" that no mixing could remove. It was replaced on 2026-11-17.
  - The P-47 recipes use `specflat` (`spectral_flatten`: slow tone-colour changes evened out per band). Without it the approach's dark-far start and bright-near end met at every seam, a once-per-loop whoosh.
  - Results: radial lines now pulse 32–39 % (V-12 loops 37–45 %), and the seam tone jump is about 1 dB (was 2.6–4.9).
  - `vinline_high` (P-51 receding) still has a 3.1 dB seam jump and doesn't use `specflat` yet.
  - V-12: Bf 109 DB 601 warm-up/run-up and P-51 take-off; a Merlin on a test stand (no prop) for `vinline_mid_off`; a PT6 floatplane for the whine/roar (harmonic/noise separation) and propeller. Each recipe gives the section, cylinder count and the recording's cycle frequency (`grid` = 0.5 order, identified from the harmonic series and the propeller blade-pass line). The loop is time-warped so cylinders × grid lands on the mixer's reference firing frequency (Doppler passes are tracked with `track=True`), level-flattened, cut to a whole number of engine cycles with an in-phase crossfade, and normalised to the **A-weighted** level of the synthesized loop it replaced (`level` in the recipe). Plain RMS matching had left the dark recordings up to 4 dB quiet and put a 7 dB dip into the V-12's mid→high crossfade. The soft limiter may take at most 1.5 dB off the 99.9th-percentile peak. Loops that would need more stay short of their level (vinline_high 1.2, turbine_roar 1.5, prop_loop 2.6, wind 3.0 dB), and `presence` (a high shelf) gives distant recordings back some top end. `_off` loops = the on-load loop thinned/darkened plus numpy crackle and pops. Start-up layers, supercharger, igniter, rasp, swish and all one-shots stay synthesized. Credits go to `Sounds/CREDITS.txt` (required by CC-BY). Not yet heard in game.

### Launch pylon (`ROPlanes-ProcPylon`)
- `Modules/ModuleROPPLaunchPylon.cs` subclasses `ModuleDecouple` (staging, ejection-force slider, "decouple" sound) and overrides `OnDecouple`. Part space: +Y forward, **+Z down towards the released aircraft**; mount face (srf attach node, orientation +Z, and stack node `mount`) at z = 0, hook face (stack node `release`, = `explosiveNodeID`) at z = height. `IsOnReleaseSide`: a part on the `release` node, or surface-attached to the pylon nearer the hook face than the mount face, is released; the parent the pylon was placed on (srf attach / `mount` node) stays. If the parent sits on the `release` node (aircraft built as the root and the pylon node-attached to it), the pylon decouples itself from it instead, so it still stays with the carrier. Release = `decouple()` of each released part, one physics frame of ejection force (stock 0.5 × force × percent each way), `onStageSeparation`, and the camera follows the "Control From Here" part if it left (like stock).
- `PartDetaches` is not overridable (sealed interface implementation), so the module **re-implements `IStageSeparatorChild`** with `new bool PartDetaches(...)` for the staging/delta-v simulation.
- Do not add an `OnDestroy`: `ModuleDecouplerBase` has a private one (unhooks `onVesselWasModified`) and Unity would only call ours.
- Shape fields (editor PAW group "Launch Pylon Shape"): `pylonLength`, `pylonHeight`, `pylonWidth`, `bottomLengthPct` (hook-face chord), `bottomWidthPct`, `sweepPct` (rake: hook face moved aft), `profileName` (Aerofoil = NACA 00xx thickness / Rounded = stadium with semi-elliptic ends / Box), `showHooks`. Changes are polled at 10 Hz in the editor; the rebuild moves the release node and the released parts with the hook face. Mass = `baseMass` + `massPerVolume` (0.2 t/m³) × enclosed volume + hooks; cost = `baseCost` + `costPerTon` × mass.
- `Geometry/PylonMeshGenerator.cs` builds the body (ruled surface between the mount-face and hook-face outlines + flat caps; tiled UVs, 1 texture tile per metre), the hooks/sway braces (separate `pylonHooks` mesh with the hardware material) and a low-res convex collider. `generate_pylon_assets.py` is a 1:1 Python port (default model + icon) and holds `LIVERIES` (B9 `pylonPaint` subtypes, first = default, `transform = pylonBody`) and the mass constants that `generate_configs.PYLON_CONFIG` writes into the cfg.
- RP-1: `unlockParts` (start node; air launches from 1946, B-29 + X-1), patch in `Compatibility/RP1_LaunchPylon.cfg`. Crossfeed off by default (`ModuleToggleCrossfeed`). Known gap: the propeller engine draws AvGas with `ALL_VESSEL_BALANCE`, which ignores crossfeed, so a carrier's propeller engines also drain a hanging AvGas aircraft until it is released. Not tested in game yet.

### FAR integration contract
The propeller `.cfg` patch registers `FARPartModuleException` (key `PartModuleName`, not `Name` — with the wrong key FAR silently ignores it and voxelizes the frozen blades, which shows up as spurious roll/yaw) naming the `*TransformName` `KSPField`s on `ModuleProceduralPropeller` (hubs, blades, discs) so FAR never voxelizes spinning parts, and sets `GeometryPartModule %forceUseColliders = True` so FAR voxelizes the procedural cowling/spinner MeshColliders. Keep the field names in the C# module, the patch text in `generate_configs.py`, and the `.mu` node names in sync.
